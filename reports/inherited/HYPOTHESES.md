## H1 统一预算优于分立预算（**已验证**）

- 陈述：同一总花费下，统一会计分配的任务成功率高于“推理预算与 agent 预算分立”。
- 实验床：E2 的 token 币种前沿 vs 解耦基线（五份私有预算、各自贪心、禁止跨轴调剂）。
- 结果：达 40% 成功处，统一 2,484 token vs 解耦 3,284 token（**1.32×**）；解耦上限
  0.6736 vs 统一 0.6906（`results/e2_allocation.json` → matched_comparisons.vs_decoupled_separate_budgets）。
- 证伪条件（预先登记）：解耦以更低或相同成本达到给定成功率 → H1 死。**未触发**。
- 附带：在 fixed-mid 自身花费处统一路由 +10.21 pt；reasoning-only +10.16 pt；agent-only +2.11 pt。

## H2 跨轴调剂优于均匀加码（**部分成立，需分基线陈述**）

- 陈述：允许预算跨五轴自由调剂的收益，大于“把每个轴一起加大”的均匀策略。
- 结果（三种非饱和基线）：匹配成功下统一路由省 3.44×（fixed-mid）、4.52×（reasoning-only）、
  2.05×（agent-only）token。
- **与 all-max 基线的关系必须诚实陈述**：匹配成功处是**平局**（0.6906 @ 145,600 token），
  因为 all-max 已在模型内可达上限。统一路由的优势集中在“达到 90% 可得成功的代价”
  （16,800 vs 145,600 = **8.67×**）。
- 敏感性：30 点网格内相对 all-max 的增益区间 [−7.14, +7.14] pt，15 例平局、8 例反转；
  反转全部发生在 agent 轴收益弱 / 饱和点远（准确率受限）的设定。**故正文不依赖该平局维度**。

## H3 最优构成随预算旋转（**已验证**）

- 陈述：最优分配不是“等比放大”，而是构成随预算改变。
- 结果：5k token → (25,1,4,2,4)；10k → b=100 但轨迹仍 1 步；20k 起才买步数（1→4→8→12→20）；
  延迟币种下 2,000 ms 预算时外网检索被压到 0 次（单次 2,233.75 ms 已超预算）。
- 证伪条件：最优各轴水平随预算近共单调 → H3 死。**未触发**（该条件与观测明显相反）。
- 单轴消融补充：最好单轴方案（reasoning 单轴拉满、其余保持中档）成功率 0.548，明显低于
  统一路由在同成本下的 0.634。

## H4（**已跑，结果与预期相反**）真实 LLM 策略下的 g_x 实测

- 陈述（原）：在真实 LLM 策略上实测 agent 轴增益 g_steps/g_tools/g_vision，可判定给定 agent
  处于「算力受限」还是「准确率受限」区间，从而预测统一路由是否仍然取胜。
- **结果（实测，非 stub）**：Qwen3-8B-AWQ + vLLM，`think_off`，672 episode，
  wall-clock 1818.175 s 逐 episode 实测求和。
- **判定：假设的用途被证伪**（不是"增益已测"）：
  1. **三轴点估计全部不可辨识**（CI95 宽度 1.0000 / 1.0000 / 0.5801，阈值 0.30）→ 不得引用任何 g_x 数值；
  2. **单调增益模型被数据拒绝**：同构 5 档成功率 0.0000/0.9375/0.8750/0.8125/0.7500，
     低档后**逐档下降**；配对 McNemar L1→L4 恶化 9 / 改善 0，exact p=0.0039；
  3. 故**「算力受限 vs 准确率受限」这一二分法的前提被数据拒绝**，不能用 g_x 去做该归类。
- **机制（可引用）**：预算越大越不验证——write/episode 1.6875→13.8125、test/episode 0.9375→0.75；
  L4 失败轨迹为 read + write×31 且无一次 test → 撞步数上限。全档失败均为 `budget:steps`，
  `parse_failures` 全档 0（think_off 生效，无格式删失混杂）。
- **易错点（必须记住）**：二次项显著性**完全由结构性地板点 L0 驱动**（含 L0：LR chi2=67.17717677530908；
  剔除 L0：0.19053330087083964, p=0.662）→ **不得**写成「存在内部最优点」，正确表述是「超过低档后单调下降」。
- 状态：**resolved-but-negative**。正文 §Discussion 保留 **conjecture→实测** 的升级，
  但升级的是「模型被拒」这一负结果，**不是**任何 g_x 数值。
- 证据：`results/h4_real_llm_gx_qwen3_8b.json`（672 记录）+ `results/h4_derived_stats.json`（派生统计）
  + `H4_FINDINGS.md`；claim ledger C34–C40；复算 `analyze_h4_result.py --refit`。
- 未做：14B 复跑；`g_search` 无法在本任务集测量（UNMEASURED，不得用别的轴凑数）。
